# V100：R535 与 vGPU 18.4/R570 一键切换

本教程只适用于已经实机验收的 `10de:1db1` Tesla V100 SXM2 16GB。默认全 1Q
部署使用与旧 RTX 宿主相同的 R535；确实需要 2Q 或 1Q+2Q 混合时，切到 vGPU
18.4/R570。两条精确合同是：

| 宿主分支 | Windows Guest | 宿主显存策略 | 用途 |
| --- | --- | --- | --- |
| R535 `535.161.05` | 正式签名 `538.33` / `31.0.15.3833` | equal 1024，`V100X-1Q` | 默认全 1Q、与旧 RTX 宿主统一 |
| R570 `570.172.07` | 正式签名 `573.48` / `32.0.15.7348` | mixed，`V100X-1Q` + `V100X-2Q` | V100 可选 18.4 分支 |

不要让同一个 Windows 母盘跨分支复用 Guest 驱动。切换宿主后，应选用对应的母盘；
旧测试 VM 不需要修，重新制作对应母盘再克隆即可。

## 安全边界

切换器不会修改 Windows BCD，不会开启 `testsigning` 或 `nointegritychecks`，也不会
创建、注册或安装测试签名/自签名内核模块。Secure Boot 未明确关闭、当前内核不是
Ubuntu GA 6.8、存在 QEMU/mdev、GPU/BDF 不匹配、官方 DEB 哈希不匹配时都会停止。
宿主密码只通过 `sudo` 当前终端输入，不得写进仓库、命令参数或配置文件。

官方资产固定放置为：

```text
/home/ubuntu/Downloads/vGPU16.4/Host_Drivers/
  nvidia-vgpu-ubuntu-535_535.161.05_amd64.deb
/home/ubuntu/Downloads/vGPU18.4/Host_Drivers/
  nvidia-vgpu-ubuntu-570_570.172.07_amd64.deb
```

## 从现有健康 R570 首次统一到 R535

先正常关闭全部 VM，第二条命令必须无输出：

```bash
cd /home/ubuntu/projects/qemu
find /sys/bus/mdev/devices -mindepth 1 -maxdepth 1 -print
./deploy/host/switch-g11-vgpu-branch.sh status
```

状态必须显示 V100、`570.172.07`、闭源 `NVIDIA` RM、空 signer 和
`r570-native`。首次执行：

```bash
sudo ./deploy/host/switch-g11-vgpu-branch.sh bootstrap-v100-r535
```

封装会停用并备份 mixed 守护、安装官方 R535、编译 Linux 6.8 适配的未签名闭源
模块、安装 R535 Hook、把 `/etc/vmate/g11-vgpu-host.conf` 与仓库本机配置同时固定为
equal 1024、建立当前精确内核的 root-only R535 恢复种子，然后自动重启。它不进入、
修改或修复任何 Guest。

适配器同时识别早期 6.8 的 `CONFIG_RETPOLINE` 和后续 Ubuntu 6.8 更新使用的
`CONFIG_MITIGATION_RETPOLINE`。若 DKMS 日志出现 `indirect jump found in
MITIGATION_RETPOLINE build`，说明正在使用不含该兼容项的旧安装包；先升级 VMate，
不要通过关闭 objtool、关闭缓解措施或给模块签名来绕过。

若首次切换在 R535 DKMS 阶段中断，升级到包含修复的 VMate 后，保持全部 VM/mdev
为空并原样重跑 `bootstrap-v100-r535`。脚本只会续跑它自己记录、内核与 GPU 都一致、
R535 恰为 `unpacked`/`half-configured` 且 R570 已移除的失败断点；后一个状态可能由
APT 在升级 VMate 时顺带配置残包产生。脚本先清除部分 DKMS 树，再从锁定哈希的官方
DEB 重装。任何不完全匹配的状态都会继续失败关闭，不会猜测恢复。

重启后只读验收：

```bash
./deploy/host/switch-g11-vgpu-branch.sh status
systemctl --no-pager --full status vmate-g11-vgpu-branch-verify.service
```

必须显示 `r535/ready`、`535.161.05`、`r535-consumer`、equal/1024MB。若显示
`pending-reboot` 或 `postboot-failed`，保持全部 VM 关闭并运行 `doctor`，不要绕过
启动门禁。

## 日常切换

每次仍须先正常关闭全部 VM并确认 mdev 为空。切到 V100 18.4：

```bash
sudo ./deploy/host/switch-g11-vgpu-branch.sh r570
```

脚本会选择 V100 native capability Hook、启用官方 heterogeneous mode、同步发布 mixed
1Q/2Q 策略并重启。对应母盘只安装 Guest `573.48`。

切回默认全 1Q：

```bash
sudo ./deploy/host/switch-g11-vgpu-branch.sh r535
```

脚本会恢复当前内核绑定的 R535 种子、停用 mixed 守护、同步发布 equal 1024 策略并
重启。对应母盘只安装 Guest `538.33`。

`--no-reboot` 只用于工程诊断；它会保留 `pending-reboot` 并禁止启动 VM，不能作为
日常免重启选项。内核升级后旧种子会按设计拒绝恢复；先回到健康 R535，在新内核上
复验后用 `init-r535 --force` 重建，不得跨内核复制模块。

## 回滚与备份

- R535 恢复种子与官方包缓存：`/var/lib/vmate/g11-vgpu-branch-switch/`；
- mixed 守护事务备份：`/var/backups/vmate-vgpu-mixed-mode/`；
- Hook 备份：`/var/backups/vgpu_unlock/`；
- 只读诊断：`./deploy/host/switch-g11-vgpu-branch.sh doctor`。

这些目录不包含宿主登录凭据，也不得提交到 Git。不要强杀仍在运行的 Guest、手工
删除被占用的 mdev，或用签名绕过替代故障定位。
