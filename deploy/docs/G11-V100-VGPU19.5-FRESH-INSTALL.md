# G-11 V100 + vGPU 19.5 全新宿主安装教程

本文是从空白 Ubuntu 24.04 宿主部署 G-11 V100 的固定流程。当前唯一支持的
R580 组合是：

- 宿主：`580.159.01`（vGPU 19.5）；
- Windows guest：`582.53` / `32.0.15.8253`；
- 宿主内核：Ubuntu GA `6.8.*-generic`；
- Windows 驱动必须保持微软/NVIDIA 正式签名。

旧 vGPU 19.0 不再是部署选项。RTX 2080/2080 Ti 继续走独立的 R535 兼容链，
不能拿本教程把它们在线升级成 R580。

## 0. 已实机验证的结论

目标机的 Tesla V100 SXM2 16GB（`0000:81:00.0`，NUMA node 1）最新验收结论：

- `V100X-1Q` + 原生 RM tuple：582.53 只加载一次，4 分钟观察中 PTE 失败、TDR、
  XID 43 和 guest driver unload 的合计计数为 0；
- 同一 1Q 写完整消费卡 RM tuple 时，可重复触发 PTE pin/translate 失败、TDR 和
  XID 43；日志中的实际改写为 `RAM_TYPE 15 -> 8`，因此生产默认关闭整个 tuple；
- 保留 per-mdev GTX 名称/FHD 合同但关闭 RM tuple 后，582.53 同样稳定；
- VM CPU 已在 V100 所在的第二颗 CPU / NUMA node 1 上做不重叠绑核验证；正式
  停机后 QEMU、mdev、swtpm 和 CPU 隔离均已回收。

这轮宿主侧物理验证没有使用 guest 凭据，因而只证明 582.53 稳定装载和数据路径
无上述错误，不能替代 Windows Device Manager Code 0、签名与显存回执。

vGPU 19.5 的官方 heterogeneous time-slice capability/mode 已启用。实际业务若全部
使用 1Q，只需创建时始终指定 `--gpu-vram 1024`；无需关闭 mixed 能力。name-only
策略下的 2Q/混搭 guest 验收应单独执行，不能沿用旧 tuple 的结论。

## 1. BIOS、硬件与显示卡

关机安装硬件后，在 BIOS/UEFI 检查：

1. Secure Boot 为 Disabled；
2. Intel VT-d/AMD IOMMU 为 Enabled；
3. Above 4G Decoding 为 Enabled；
4. 宿主主显示卡固定为 RX550 等非 V100 卡；
5. V100 所在 PCIe 根端口对应的物理 CPU 已安装并在线。

自动修复不会绕过 Secure Boot，也不会创建 MOK/自签名模块。Windows 侧禁止
`testsigning`、`nointegritychecks` 和任何 BCD 修改。

进入 Ubuntu 后先做只读盘点：

```bash
lspci -Dnn | grep -Ei 'VGA|3D|Display'
cat /sys/bus/pci/devices/0000:81:00.0/numa_node
cat /sys/devices/system/node/node1/cpulist
mokutil --sb-state
```

`SecureBoot disabled` 表示已关闭；`This system doesn't support Secure Boot`
表示当前 EFI 固件没有 Secure Boot 能力，也可继续。只有明确 `SecureBoot enabled`
时必须进 BIOS 关闭；其他无法识别的输出仍按失败处理，自动修复不会用 MOK 或自签名
模块绕过。

教程中的 `0000:81:00.0` 只代表已验收机器；新主机必须替换成自己的完整 BDF。

## 3. 推荐：用 VMate 修复中心安装

安装包含当前 G-11 deploy 树的 VMate `.deb`，然后打开：

```text
G-11 -> 修复中心 -> 自动修复
```

修复中心会按 V100 的实际 BDF 执行并复检：

- Ubuntu 24.04、GA 6.8、IOMMU、Secure Boot、双显卡与 NUMA；
- apt 依赖和 `/opt/g11/python` 的固定 WinRM 运行时；
- 精确哈希的 `580.159.01` host 包及 DKMS 隔离编译门禁；
- R580 identity Hook、`schema=2` 状态，以及 V100 的 name-only / 原生 RM tuple
  稳定策略；
- V100 heterogeneous 1Q/2Q 模式、开机/复位恢复 timer；
- mdev helper、CPU/NUMA 隔离、性能 helper 和显式宿主配置；
- VMate 包内 G-11 QEMU 的独立进程身份门禁；它接受
  `qemu-system-x86_64.g11.real`，明确拒绝 V-11 的
  `qemu-system-x86_64.real`，异常退出后按 VM UUID 回收 mdev。

首次修复需下载依赖、校验驱动并编译 Hook，视软件源速度通常需要
`10–30` 分钟；期间不要关闭 VMate 或重复点击。它可能分两阶段：第一阶段安装/
选择 GA 6.8 并提示重启；重启进入 6.8 后，再次点“自动修复”完成驱动、
Hook 和 mixed mode。它不会自动重启宿主。

Ubuntu DKMS 即使在 Secure Boot 已关闭时也可能自动用本机 MOK 给模块签名。VMate
会显式关闭本次构建的签名动作，并要求 `modinfo -F signer nvidia` 为空。若发现旧的
MOK 签名模块，自动修复只在无 QEMU/mdev 时重建磁盘模块，提示冷重启；不会删除、
创建或注册 MOK，也不会在线卸载正在运行的驱动。修复入口固定禁用 Git/systemd
分页器，失败时修复中心会显示最近的真实输出，不会再卡在 `Press RETURN`。

也可从终端调用同一受管入口；BDF 和 UID 必须来自本机，不要照抄：

```bash
sudo /opt/vmate/repair-env.sh g11 \
  --target-bdf 0000:81:00.0 \
  --model v100 \
  --target-uid "$(id -u)"
```

## 4. 无 VMate 时的手工封装流程

### 4.1 安装依赖和受管 Python

```bash
sudo apt update
sudo apt install -y --no-install-recommends --no-upgrade \
  bash sudo pciutils util-linux procps psmisc lsof iproute2 bridge-utils \
  network-manager netplan.io qemu-system-x86 qemu-utils ovmf swtpm swtpm-tools \
  xorriso ffmpeg jq socat rsync ntfs-3g numactl diffutils build-essential \
  pkg-config git curl ca-certificates kmod mokutil dkms \
  linux-generic linux-headers-generic python3 python3-venv python3-pip \
  python3-requests python3-cryptography p7zip-full zip unzip mtools

cd /home/ubuntu/projects/qemu
sudo ./deploy/host/install-g11-python-runtime.sh
./deploy/host/install-g11-python-runtime.sh --check
```

运行时只安装哈希锁定的 `pypsrp 0.9.1` 与 `pyspnego 0.12.2`，位置为
`/opt/g11/python`；不修改系统 Python，也不保存凭据。

Hook 优先复用当前普通用户 `~/.cargo` 中的 rustup toolchain；若不存在，
`setup-vgpu-unlock.sh` 会安装 minimal stable toolchain。不需要安装 Ubuntu 的
`cargo`/`rustc` 包及其 LLVM 依赖。修复入口对已满足的 apt 包使用
`--no-upgrade`，避免顺带升级与 G-11 无关的宿主组件。已通过固定版本/
摘要复检的 `/opt/g11/python` 也会直接复用，不每次重建虚拟环境。

### 4.2 进入 GA 6.8，再装 host driver

```bash
uname -r
```

必须为 `6.8.*-generic`。如果刚安装 GA 内核，先重启并再次确认。然后：

```bash
HOST_DEB=/home/ubuntu/Downloads/vGPU19.5/Host_Drivers/nvidia-vgpu-ubuntu-580_580.159.01_amd64.deb
NO_SIGN_FILE=/run/vmate-dkms-module-signing-disabled
test ! -e "$NO_SIGN_FILE"
if grep -REqs '^[[:space:]]*(export[[:space:]]+)?sign_file[[:space:]]*=' \
    /etc/dkms/framework.conf /etc/dkms/framework.conf.d 2>/dev/null; then
  echo '已有自定义 DKMS sign_file；停止并先审计本机策略' >&2
  exit 1
fi
sudo env sign_file="$NO_SIGN_FILE" apt install -y "$HOST_DEB"
test -z "$(modinfo -k "$(uname -r)" -F signer nvidia 2>/dev/null)"
test "$(modinfo -k "$(uname -r)" -F license nvidia 2>/dev/null)" = NVIDIA
sudo reboot
```

重启后：

```bash
cat /sys/module/nvidia/version
modinfo -F license nvidia
test -z "$(modinfo -F signer nvidia)" && echo 'NVIDIA module: unsigned'
systemctl is-active nvidia-vgpu-mgr.service
nvidia-smi -q -i 0000:81:00.0 | sed -n '/vGPU Device Capability/,+12p'
```

版本必须精确为 `580.159.01`。

### 4.3 安装 R580 Hook 与 mixed-mode 守护

先确认所有 vGPU VM 已关闭且没有 mdev：

```bash
find /sys/bus/mdev/devices -mindepth 1 -maxdepth 1 -print
```

输出为空后执行：

```bash
cd /home/ubuntu/projects/qemu
sudo -v
BUILD_DIR=/home/ubuntu/src/vgpu_unlock-rs-g11 \
  ./deploy/host/setup-vgpu-unlock.sh --restart-manager

sudo ./deploy/host/install-vgpu-mixed-mode.sh --bdf 0000:81:00.0
sudo /usr/local/libexec/qemu-vgpu-mixed-mode status 0000:81:00.0
```

Hook 在 R580 上保持 `unlock=false`：V100 的原生 vGPU 能力仍由官方驱动提供，
Hook 只保留经过验证的每 mdev 名称/显示合同；宿主策略写入
`VGPU_RM_FB_IDENTITY_MODE=off`，不改写 RM framebuffer tuple，也不会要求或安装
任何 Windows 测试驱动。

### 4.4 生成宿主策略

V100 SXM2 16GB、允许 1Q/2Q：

```bash
./deploy/configure-g11-vgpu-host.sh \
  --preset v100-sxm2-16gb \
  --gpu 0000:81:00.0
```

若确定整池永远只用 1Q，也可生成 equal 策略：

```bash
./deploy/configure-g11-vgpu-host.sh \
  --preset v100-sxm2-16gb \
  --fb-mode equal --tier 1024 \
  --gpu 0000:81:00.0 --force
```

切换 mixed/equal 前必须关闭该卡上全部 VM/mdev。PCIe V100 按实际容量改用
`v100-pcie-16gb` 或 `v100-pcie-32gb`，不得猜测 profile 前缀。

## 5. 准备 Windows ISO 和正式 guest driver

本项目固定 ISO：

```bash
sha256sum /home/ubuntu/images/iso/win10.iso
```

期望：

```text
d485d370406cbcb68959718817bd12ed87e537a14c885f84962e07136fc4a049
```

把 guest 原包放进受管 staging（文件名必须保持不变）：

```bash
install -d -m 0755 /home/ubuntu/images/staging
install -m 0644 \
  /home/ubuntu/Downloads/vGPU19.5/Guest_Drivers/582.53_grid_win10_win11_server2022_server_2025_dch_64bit_international.exe \
  /home/ubuntu/images/staging/
```

驱动安装器会再次核对外层 EXE、内层 `setup.exe`、INF 版本与签名收据。

基础镜像只制作一份：推荐在 1Q/1024MB 模板 VM 中安装上述未修改的
官方 `582.53` Guest Driver，完成 Windows、VirtIO/客户工具、Code 0 和
WHCP/生产签名验收后，再按
[`G11-SYSPREP-PRIVATE-BASE.md`](G11-SYSPREP-PRIVATE-BASE.md) 封装。不要为 2Q
另做一份镜像；克隆时由宿主 mdev profile 选择 1Q 或 2Q，Guest Driver
完全相同。显存配额由官方 mdev profile 决定；Hook 只投影名称/FHD，RM
framebuffer 身份保留 NVIDIA 原生值。整个过程不改 BCD，不使用 `testsigning`、
`nointegritychecks` 或测试/自签驱动。

同一份母盘也可以先在本机 RTX 2080 的显式 `r580-lab` 分支安装/更新 Guest
`582.53`，步骤见
[`G11-RTX2080-R535-R580-SWITCH.md`](G11-RTX2080-R535-R580-SWITCH.md)。
这只能证明 Guest 内容可安装：本机该组合曾短时正常显示并达到 Code 0，随后出现
XID 43/TDR/SDL 黑屏。最终冷启动、Code 0、1Q/2Q、无 XID 和封盘验收仍必须在
V100 上完成。

## 6. 创建 1Q VM、装 Windows 和 GRID

```bash
cd /home/ubuntu/projects/qemu
./deploy/scripts/vmctl.sh create 1 --gpu-vram 1024
./deploy/scripts/vmctl.sh start 1 \
  --install /home/ubuntu/images/iso/win10.iso \
  --fresh-unattended --lab-usernet
```

Windows/WinRM 就绪后，通过安全运行时渠道提供 guest 凭据；示例只写变量名：

```bash
read -rsp 'Windows password: ' GUEST_PASS; echo
export GUEST_PASS
GUEST_USER=Administrator \
  ./deploy/scripts/vmctl.sh driver-install 1 --lab-usernet --start
unset GUEST_PASS
```

密码不应出现在仓库、配置文件或命令参数中。若使用正常 `br0`，去掉
`--lab-usernet`。

## 7. 验收清单

每台 VM 至少确认：

- Device Manager：NVIDIA 设备 Code 0；
- 驱动：`582.53` / `32.0.15.8253`，签名状态为 WHCP/正式签名；
- 1Q 显存为 1024MB；若测试 2Q则为 2048MB；
- Windows 完整关机后 QEMU、mdev 和 CPU 隔离状态均被回收；
- VMate 安装包首次实启没有 `cpu-isolate: 需要 root`，且日志出现
  `CPU 隔离完成`；不能用 `--cpu-isolate=false` 代替发行验收；
- 宿主 `journalctl -u nvidia-vgpu-mgr` 与 `dmesg` 无新增 Xid/AER/MCE；
- mixed 测试时两台 VM 分别为 1Q/2Q，并能同时运行、顺序关机和同时关机。

宿主复检：

```bash
./deploy/host/install-g11-python-runtime.sh --check
sudo /usr/local/libexec/qemu-vgpu-mixed-mode status 0000:81:00.0
systemctl is-active nvidia-vgpu-mgr.service vmate-vgpu-mixed-mode.timer
grep '^VGPU_RM_FB_IDENTITY_MODE=off$' /etc/vmate/g11-vgpu-host.conf
grep -E '^(schema|driver_family|driver_version|r580_ram_type_policy|r580_unlock_policy)=' \
  /etc/vgpu_unlock/g11-hook.state

# 把时间替换为本次 VM 启动时间；期望输出 0
journalctl -u nvidia-vgpu-mgr --since 'YYYY-MM-DD HH:MM:SS' --no-pager | \
  grep -cE 'Failed to (pin|translate)|Timeout occurred|XID 43|Guest driver unloaded'
```

`Unlicensed (Unrestricted)` 不是本次 tuple 故障的判据：失败组和稳定组的授权日志
相同，而稳定组没有 XID。生产是否要求 DLS `Licensed` 仍按业务授权策略单独验收。

## 8. 故障回退

任何回退前先正常关闭全部 VM，并确认 `/sys/bus/mdev/devices` 为空。

- Hook 每次安装的备份位于 `/opt/vgpu_unlock/backups/`；
- mixed-mode 受管文件备份位于 `/var/backups/vmate-vgpu-mixed-mode/`；
- VMate 的内核、源和驱动变更审计位于
  `/var/backups/vmate/g11-v100-r580/`；
- VM 磁盘和配置不应通过卸载 host driver 回退；先单独备份 VM bundle；
- 需要移除 R580 时，先保存日志和上述备份，再从本地控制台执行包卸载并重启；
  不要在线卸载仍被 mdev/QEMU 使用的 NVIDIA 模块。

不要用启用 Windows 测试签名、修改 BCD、关闭完整性校验或安装自签内核驱动的方式
“修复” Code 43/Code 0 问题。
