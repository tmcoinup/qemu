## 2. 方案边界

当前实现是**系统级浅层硬件身份投影**，不是 GPU-Z 单独适配：

- QEMU PCI 配置空间的物理主 ID 保持 `1AF4:1050`，由 `VioGpuDod` 正常绑定。
- Windows PnP HardwareID 使用同一 devnode 的规范逻辑首项，例如
  `PCI\VEN_10DE&DEV_1C82&SUBSYS_00007377&REV_A1`，随后逐项保留原始完整
  `1AF4:1050` 数组。真实 InstanceId、BDF、Service 和 Driver 仍为物理 carrier，
  MULTI_SZ 中的多条字符串不会创建第二张显卡。
- Display Enum `FriendlyName` 与系统级双架构 NVAPI 统一读取 profile 对应的标准
  `NVIDIA GeForce GTX 1050 Ti` 身份。部分 WMI/`Win32_VideoController` provider
  仍可能返回为 WHCP 驱动关联保留的 stock `DriverDesc`。
- GPU-Z 2.70 是 32 位主程序并带 64 位辅助进程，因此正式方案同时发布受摘要约束的
  `SysWOW64\nvapi.dll` 与 `System32\nvapi64.dll`。它们属于系统级公共 reader，不要求
  GPU-Z 旁置 DLL、环境变量、helper 或单独启动方式。
- NVAPI `GetPCIIdentifiers` 的主 `deviceId` 使用物理 `1AF4:1050` 作为
  PnP/BDF/NVAPI 跨接口去重键；external device、AIB SUBSYS/REV 与标准型号保持逻辑
  NVIDIA 身份。legacy MemoryInfo 的 4 GiB 为 `4194304 KiB`，MemoryInfoEx 为
  `4294967296 bytes`。
- 读取上述 Windows 公共接口的其它软件也应看到同一身份；直接读取 PCI 配置空间、
  VirtIO capability、驱动 service、OpenGL/Vulkan renderer 的软件仍可能识别
  VirtIO/virgl。这是用户后来明确选择的“旧版浅层处理办法”的固有限制。
- 当前 Windows `VioGpuDod` 路径没有客体 virgl 3D；宿主启用
  `virtio-vga-gl/virgl` 不等于 Windows guest 获得可用 3D。浅层 PCI/NVAPI 投影只改变
  身份读取结果，不会凭空增加 CUDA、真实 NVIDIA 驱动、可分配显存或 3D 性能。

若以后改成 QEMU 配置空间直接暴露 `10DE:1C82`，那是另一项“深层仿真”工程，会改变
驱动匹配和 Code 43 风险，不能与本浅层方案混称。

## 4. VM2 三次失败与已经完成的修复

### 4.1 第一次：删除不存在任务被误判为致命错误

实跑包 SHA-256：
`5db2ee0e74210c477b6ce0f6f3ceb64a259782f6c419d9216629a3a13cf93407`

现象：

- 电源策略全部成功。
- `apply-gpu-spoof.ps1` 在安装启动刷新任务前执行
  `schtasks.exe /Delete /TN StealthGPU-RefreshName /F`。
- 首次安装时任务本来就不存在；`schtasks.exe` 把“找不到文件”写到 stderr，在全局
  `$ErrorActionPreference='Stop'` 下被提升成终止错误。
- durable identity/NVAPI 事务按设计回滚，所以 GPU-Z 变成空白。

已修：

- 改用 Windows ScheduledTasks API。
- 完整枚举必须成功后，才按根目录和精确任务名匹配。
- 任务存在才删除；删除后再次完整枚举并确认消失。
- 查询、删除和复读的真实故障继续 fail-closed。

### 4.2 第二次：可选 DEVPKEY 诊断触发 Access denied

实跑包 SHA-256：
`02c45437f5895eb0507a371685b30d75d06ea41546da20afa7d2803243a602b9`

现象：

- 已越过任务创建，WMI 当时已经显示 `NVIDIA GeForce GTX 1050 Ti`。
- 尾部旧版诊断用 `reg.exe query` 读取 TrustedInstaller 保护的 DriverProvider DEVPKEY。
- `Access is denied` 再次被严格错误模式当成事务失败并回滚。

已修：

- 删除这段不参与正式身份验收、也不影响其它软件公共读取接口的旧诊断。
- 同时删除只为该诊断服务的 `Convert-ToRegPath`、`fmtDev` 和临时匹配结构。
- `apply-gpu-spoof.ps1` 当前非空、非注释代码行为 `495`，没有超过 500 行限制。

### 4.3 第三次：NVAPI Unchanged 收据空路径 Finalize

实跑包 SHA-256：
`ecae21618730d7f3d5b515fb91538b8cdbeb9f4c01e98cf32db5a41fbb006a6b`

现象：

- identity Stage、Class/WMI 提交、两个计划任务、PnP scan、WMI 验证均成功。
- WMI 实际输出名称为 `NVIDIA GeForce GTX 1050 Ti`，分辨率 `1920x1080`。
- VM2 的两份系统 NVAPI DLL 已经是当前摘要，因此 durable receipt 动作为
  `Unchanged`，`Stage/Backup/Discard` 合法地为空。
- `Finalize-NvapiProjectionReceipt` 无条件把空 `Discard` 传入
  `Test-Path -LiteralPath`，触发参数绑定失败，外层返回 1。

已修：

- `nvapi-system-transaction.ps1` 仅在 `Discard` 非空时检查其存在性。
- 新增“两个目标已是 Current、收据为 Unchanged、Finalize 幂等成功并删除收据”的
  动态回归测试。
- 修复后的正式 EXE 即本文件第 1 节所列 `82fc...`，尚待 VM2 实跑。
