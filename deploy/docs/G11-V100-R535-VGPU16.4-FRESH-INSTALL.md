# G-11 V100 + vGPU 16.4/R535 全新安装教程

这是当前 V100 **全 1Q（1024MB）业务的推荐生产路线**。已验证组合固定为：

| 层 | 固定版本/策略 |
|---|---|
| Ubuntu | 24.04，GA `6.8.*-generic` |
| NVIDIA host | vGPU 16.4 / `535.161.05`，官方闭源 RM |
| Windows guest | 正式签名 GRID `538.33` / `31.0.15.3833` |
| V100 profile | 与实卡 SKU 匹配的 `V100*-1Q`，整卡 `equal + 1024MB` |
| identity Hook | R535 精确 ABI；每 mdev 消费卡身份和 RM framebuffer 字段 |
| 宿主 NUMA | CPU node=`all`；Guest RAM=`interleave all` |

不启用 Windows `testsigning`、`nointegritychecks`，不改 BCD，不安装任何测试签名或
自签名内核驱动。宿主模块要求 Secure Boot 关闭并保持未签名；Guest Driver 使用
NVIDIA/Microsoft 正式签名。驱动包、license token 和任何密码都不得写入仓库。

## 0. 已实机验证到什么程度

2026-08-31 在 V100 SXM2 16GB 目标机完成了以下闭环：

- host `535.161.05`、guest `538.33`、`V100X-1Q/1024MB`；
- R535 Hook 的运行日志确认 `RAM_TYPE 15 -> 8`、位宽 `4096 -> 128`；
- Windows Device Manager Code 0，驱动 WHCP/正式签名，运行态显示 GTX 750 / 1024MiB；
- SDL 1920×1080 连续运行约 9 分钟，新增 XID 43、Guest TDR、PTE pin/translate、
  display-copy timeout 和 guest driver unload 均为 0；
- 正常关机后 QEMU、mdev、TPM 和 CPU 隔离全部回收，`qemu-img check` 错误为 0。

显存厂家字段已经配置，但本轮 Manager 没有查询该字段，所以**不能写成已验证**；
RAM_TYPE 与位宽则有实际 Hook 查询/改写日志。这个结果只覆盖 1Q，不外推到 2Q 或
1Q/2Q 混搭。DLS 授权状态与本轮 XID/TDR 结果无因果关系，授权仍按业务单独验收。

R580/19.5 在相同 V100 上保留 name-only 的可选路线；它的完整消费卡 RM tuple 曾触发
XID/TDR。业务既然统一 1Q，就优先使用本页的 R535/16.4 合同，避免维护两套 Guest
Driver 和两套运行策略。

## 1. BIOS、双 CPU、显示卡

关机安装硬件后，在 BIOS/UEFI 确认：

1. Secure Boot = Disabled；
2. VT-d/IOMMU = Enabled；
3. Above 4G Decoding = Enabled；
4. RX550 等非 V100 卡为宿主主显示卡；
5. V100 所在 PCIe 根端口对应的第二颗 CPU 已安装并在线。

进入 Ubuntu 后只读检查：

```bash
lspci -Dnn | grep -Ei 'VGA|3D|Display'
cat /sys/bus/pci/devices/0000:81:00.0/numa_node
cat /sys/devices/system/node/node1/cpulist
mokutil --sb-state
uname -r
```

`0000:81:00.0` 和 `node1` 只是已测机器的值，新主机必须按实机替换。若 V100 所在
NUMA node 没有在线 CPU，VMate 会停止修复。V100 不负责宿主桌面输出；显示器接
RX550 没画面属于 BIOS/宿主显示栈的独立问题，不影响 V100 mdev，但正式交付前仍应
单独重启检查。

默认策略不是“整台宿主只用第二颗 CPU/内存”：它生成
`VGPU_HOST_CPU_NODE_BIND=all` 与 `VGPU_HOST_MEMORY_NODE_BIND=all`，启动时使用
`--cpunodebind=all --interleave=all`。两颗 CPU 和两路内存条都可供 8 台 VM 使用，
但不会增加 Windows 看到的 vCPU 数量。node0 页面访问 node1 下的 V100 时会经过
CPU 间互联，这是使用全部内存的预期代价。

只有明确显示 Secure Boot 已关闭（或固件明确不支持 Secure Boot）、当前内核为
`6.8.*-generic` 才继续。自动修复不会注册 MOK、创建自签名模块或修改启动安全策略。

## 2. 放置并核验 vGPU 16.4 原包

保持 NVIDIA 原目录结构：

```text
/home/ubuntu/Downloads/vGPU16.4/
├── Host_Drivers/
│   └── nvidia-vgpu-ubuntu-535_535.161.05_amd64.deb
└── Guest_Drivers/
    └── 538.33_grid_win10_win11_server2019_server2022_dch_64bit_international.exe
```

核验：

```bash
sha256sum \
  /home/ubuntu/Downloads/vGPU16.4/Host_Drivers/nvidia-vgpu-ubuntu-535_535.161.05_amd64.deb \
  /home/ubuntu/Downloads/vGPU16.4/Guest_Drivers/538.33_grid_win10_win11_server2019_server2022_dch_64bit_international.exe
```

必须分别得到：

```text
2786430d32b6894f360ce0c249b29f849ae963c186840547151ed00d0feaebb9  host DEB
aaa3080c0b7e3a6fbe825a05725f4171c75072faa8b667d97556c1605a219ddd  guest EXE
```

任一摘要或 DEB 包名、版本、架构不符都立即停止。

## 3. 推荐：安装 VMate 后点一次自动修复

安装当前 VMate `.deb` 后打开：

```text
G-11 -> 修复中心 -> 自动修复
```

也可从终端运行相同的受管入口：

```bash
sudo /opt/vmate/repair-env.sh g11 \
  --target-bdf 0000:81:00.0 \
  --model v100 \
  --target-uid "$(id -u)"
```

修复中心会：

- 识别实际 V100 BDF、双显卡、IOMMU、NUMA、Secure Boot 和 GA 6.8；
- 从用户 Downloads 或 root 受管目录选择**精确哈希**的 R535 资产；
- 在官方源码上应用精确哈希约束的 Linux 6.8 DKMS 兼容补丁；
- 编译并复检未签名的闭源 `nvidia` 与 `nvidia-vgpu-vfio` 模块；
- 安装 R535 Hook、mdev/CPU/性能 helper，并写入 `V100X-1Q`（或对应 SKU）
  的 `equal + 1024MB` 宿主策略；CPU 和内存 node 默认都写为 `all`；
- 把 Hook 源码固定在目标普通用户的 `~/src/vgpu_unlock-rs-g11`；即使由 root 入口
  启动，也不会尝试让普通用户写入 `/root`；
- 锁定已验证内核，并在每次完成后重新检查修复中心状态。

首次安装可能要求正常重启。它不会自动重启；重启进入同一个 GA 6.8 内核后，再点一次
“自动修复”完成 Hook 和宿主策略。检测到已经加载的 R535 或 R580 时，VMate 保留当前
分支，不做在线跨分支升级。

## 4. 无 VMate 时使用封装脚本

先关闭全部 vGPU VM，并确认没有 mdev：

```bash
find /sys/bus/mdev/devices -mindepth 1 -maxdepth 1 -print
```

输出必须为空。然后执行精确驱动安装器：

```bash
cd /home/ubuntu/projects/qemu
sudo ./deploy/host/install-v100-r535-host.sh \
  --bdf 0000:81:00.0 \
  --driver-deb /home/ubuntu/Downloads/vGPU16.4/Host_Drivers/nvidia-vgpu-ubuntu-535_535.161.05_amd64.deb
```

该安装器中的 `patch-nvidia-vgpu-r535-linux68.py` 只处理 R535.161.05 到 Linux 6.8 的
内核 ABI 变化，包括 VFIO/IOMMUFD、eventfd、IOMMU 和 DRM 编译接口。它不修改 NVIDIA
RM 功能、不伪造设备身份，也不涉及 Windows 驱动。补丁器同时固定补丁前/后的七个
源码 SHA-256；遇到未知或只改了一半的源码树会拒绝继续。

如提示重启，正常执行：

```bash
sudo reboot
```

重启后复检并安装 Hook：

```bash
cat /sys/module/nvidia/version
test "$(modinfo -F license nvidia)" = NVIDIA
test -z "$(modinfo -F signer nvidia)"
test -z "$(modinfo -F signer nvidia-vgpu-vfio)"
systemctl is-active nvidia-vgpu-mgr.service

cd /home/ubuntu/projects/qemu
sudo -v
BUILD_DIR=/home/ubuntu/src/vgpu_unlock-rs-g11 \
  ./deploy/host/setup-vgpu-unlock.sh --restart-manager
./deploy/configure-g11-vgpu-host.sh \
  --preset v100-sxm2-16gb \
  --fb-mode equal --tier 1024 \
  --cpu-node-bind all \
  --gpu 0000:81:00.0 --force
```

必须按真实 V100 SKU选择 preset：

```text
v100-pcie-16gb   v100-pcie-32gb
v100-sxm2-16gb   v100-sxm2-32gb
v100s-pcie-32gb  v100-fhhl-16gb
```

R535/16.4 不走 R580 mixed-mode helper。整个物理 V100 固定 1Q/equal；切换策略前始终
要求所有 VM/mdev 已停止。

## 5. Windows ISO、Guest Driver 与母盘

固定 ISO 路径：

```text
/home/ubuntu/images/iso/win10.iso
```

把正式 Guest Driver 放到 staging：

```bash
install -d -m 0755 /home/ubuntu/images/staging
install -m 0644 \
  /home/ubuntu/Downloads/vGPU16.4/Guest_Drivers/538.33_grid_win10_win11_server2019_server2022_dch_64bit_international.exe \
  /home/ubuntu/images/staging/
```

基础镜像只需制作一份：在 1Q/1024MB VM 内安装 Windows、VirtIO/客户工具和未经修改
的正式 `538.33`，确认 Device Manager Code 0、WHCP/正式签名和 1024MiB 后，再按
[`G11-SYSPREP-PRIVATE-BASE.md`](G11-SYSPREP-PRIVATE-BASE.md) 封装。后续所有 VM 都
按 1Q 克隆，不为 2Q 另做母盘。

示例：

```bash
cd /home/ubuntu/projects/qemu
./deploy/scripts/vmctl.sh create 1 --gpu-vram 1024
./deploy/scripts/vmctl.sh start 1 \
  --install /home/ubuntu/images/iso/win10.iso \
  --fresh-unattended --lab-usernet
```

Windows 凭据只通过当前 shell 的安全运行时渠道提供：

```bash
read -rsp 'Windows password: ' GUEST_PASS; echo
export GUEST_PASS
GUEST_USER=Administrator \
  ./deploy/scripts/vmctl.sh driver-install 1 --lab-usernet --start
unset GUEST_PASS
```

不得把密码放入命令参数、仓库、`vm.conf` 或教程。

## 6. 封盘验收

每台正式母盘/克隆至少确认：

- Device Manager NVIDIA 设备 Code 0；
- Guest Driver `538.33` / `31.0.15.3833`，WHCP/正式签名；
- 运行态显存 1024MiB，消费卡名称符合选定 G-11 profile；
- SDL 实际显示、分辨率和业务负载正常；
- 宿主没有新增 XID 43、TDR、PTE pin/translate 或 display-copy timeout；
- 正常关机后 QEMU、mdev、swtpm 和 CPU 隔离全部回收；
- `qemu-img check` 不报告磁盘错误。

宿主复检：

```bash
sudo grep -E '^(VGPU_HOST_FB_MODE|VGPU_HOST_FB_TIER_MB|VGPU_HOST_(CPU|MEMORY)_NODE_BIND|VGPU_RESOURCE_PROFILE|VGPU_RESOURCE_FB_MB|VGPU_RM_FB_IDENTITY_MODE)=' \
  /etc/vmate/g11-vgpu-host.conf
grep -E '^(schema|driver_family|driver_version|r535_unlock_policy)=' \
  /etc/vgpu_unlock/g11-hook.state
systemctl is-active nvidia-vgpu-mgr.service

# 把时间替换为本次启动时间；无匹配才通过
{
  journalctl -k --since 'YYYY-MM-DD HH:MM:SS' --no-pager
  journalctl -u nvidia-vgpu-mgr --since 'YYYY-MM-DD HH:MM:SS' --no-pager
} | grep -Ei 'Xid|TDR|Failed to (pin|translate)|display.*copy.*timeout|Guest driver unloaded'
```

最后一条 `grep` 返回 1 表示没有匹配，这是期望结果。`Unlicensed (Unrestricted)`
不能解释 RAM_TYPE/XID：DLS 是否需要 `Licensed` 是独立的授权验收项。

CPU/RAM 验收必须在配置生成或 VMate 修复完成后，完整关闭并重新启动 VM才生效。检查
QEMU 主进程及任务线程 `/proc/<PID>/status` 的 `Cpus_allowed_list`，以及
`/proc/<PID>/numa_maps` 中 ram0 的 `interleave:<全部 node>` 和各 `N<node>=...`。
正常共享启动使用 `--cpu-isolate=false`；显式开启隔离会再次缩小 CPU/cpuset。
完整的 8 台停机、PID 获取和验收命令见
[`G11-VGPU-HOST-QUICKSTART.md`](G11-VGPU-HOST-QUICKSTART.md) 第 5 节。

## 7. 故障处理与边界

- 发现活动 mdev 时，不卸载模块、不重启 Manager，先正常关闭对应 VM；
- 发现非 `535.161.05` 或已安装 R580 时，安装器拒绝自动覆盖；
- 发现模块 signer 非空时，不沿用未知 MOK/自签模块，先保存诊断并安排冷维护；
- 发现 Secure Boot enabled 时，进入 BIOS 关闭，不能用 MOK/自签绕过；
- 如需回滚双路 CPU/内存策略，先正常关闭全部 VM并确认 mdev 为空，再用相同
  preset/equal/1024 参数生成 `--cpu-node-bind local --memory-node-bind local`，重启
  VM并复查 `Cpus_allowed_list`/`numa_maps`；VMate 再次自动修复会恢复两项默认 `all`；
- 2Q、1Q/2Q 混搭或其他 R535/R580 小版本都不属于本页已验证合同；
- 显存厂家在 Manager 未查询前只能记为“已配置、未证明”，不能伪造验收结论。

不要用修改 BCD、关闭完整性校验、测试签名或自签 Windows 内核驱动的方式处理
Code 43、XID 或 TDR。
