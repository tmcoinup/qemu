# RTX 2080：R535 稳定分支与 R580 母盘实验分支一键切换

这份教程只适用于当前已验证的单 NVIDIA GPU 宿主：

- GPU：`10de:1e82` RTX 2080（本机 16 GiB 显存）；
- 内核：创建 R535 恢复种子时的精确 Ubuntu GA 6.8 内核；
- 稳定分支：host `535.161.05` + guest `538.33`；
- 实验分支：host `580.159.01` 闭源 RM + guest `582.53`；
- 整张 RTX 2080 的资源策略继续固定为 equal `1024MB`。

脚本不会把 RTX 2080 的 R580 标记为生产可用。本机实测 R580 Guest 能安装、
曾显示正常桌面且 Device Manager 为 Code 0，但正常 1Q 运行随后出现 XID 43、
Guest TDR、display-head copy 超时和 SDL 黑屏。R580 只用于准备/更新母盘内容；
最终冷启动、Code 0、1Q/2Q、无 XID 和封盘验收必须在 V100 上完成。

## 1. 安全边界

脚本固定遵守以下规则：

- 不改 Windows BCD；
- 不开启 `testsigning` 或 `nointegritychecks`；
- 不安装测试签名或自签名内核驱动；
- Ubuntu DKMS 构建时显式关闭默认 MOK 自动签名，并逐个复验模块 signer 为空；
- Secure Boot 没有明确关闭时直接退出；
- 有 QEMU 或 mdev 时直接退出，不强杀 Guest；
- 只接受 SHA256、包名、版本和架构全部精确匹配的两个 NVIDIA 官方 DEB；
- R580 在 RTX 上强制使用官方包内的闭源 RM 源码，不接受 open kernel module；
- 密码、token 和 NVIDIA 专有文件都不写入 Git。

R535 的本机适配源码和内核模块属于 NVIDIA 专有、内核绑定资产，只保存在：

```text
/var/lib/vmate/g11-vgpu-branch-switch/
```

归档和缓存包均为 root-only；只读状态元数据允许普通用户查看。机器交给其他人时
保留该目录即可，不要把它提交或复制进 VMate 安装包。

全新安装先补齐宿主依赖（VMate 自动修复也会安装这些依赖）：

```bash
sudo apt update
sudo apt install -y dkms "linux-headers-$(uname -r)" mokutil pciutils zstd
```

## 2. 第一次初始化

先确认本机处于健康 R535：

```bash
cd /home/ubuntu/projects/qemu
./deploy/host/switch-g11-vgpu-branch.sh status
```

期望看到：

```text
已加载驱动     : 535.161.05
内核 RM        : NVIDIA
模块签名者     : none（未签名）
Hook 策略      : r535-consumer
宿主 FB 策略   : equal/1024MB
```

第一次只需执行一次：

```bash
sudo ./deploy/host/switch-g11-vgpu-branch.sh init-r535
```

它会校验并缓存：

```text
/home/ubuntu/Downloads/vGPU16.4/Host_Drivers/
  nvidia-vgpu-ubuntu-535_535.161.05_amd64.deb

/home/ubuntu/Downloads/vGPU19.5/Host_Drivers/
  nvidia-vgpu-ubuntu-580_580.159.01_amd64.deb
```

若文件放在别处，必须给绝对路径：

```bash
sudo ./deploy/host/switch-g11-vgpu-branch.sh init-r535 \
  --r535-deb /绝对路径/nvidia-vgpu-ubuntu-535_535.161.05_amd64.deb \
  --r580-deb /绝对路径/nvidia-vgpu-ubuntu-580_580.159.01_amd64.deb
```

`init-r535` 只捕获当前驱动资产并写入本机 root-only 种子，不会关 VM 或改驱动；
仍建议在空闲时运行。
已存在种子时默认拒绝覆盖。只有重新验证过健康 R535 后，才使用 `--force` 重建。

## 3. 日常一键切换

先正常关闭所有 VM：

```bash
./deploy/scripts/vmctl.sh stop 1
find /sys/bus/mdev/devices -mindepth 1 -maxdepth 1 -print
```

第二条必须没有输出。

切到 R580 母盘实验档：

```bash
sudo ./deploy/host/switch-g11-vgpu-branch.sh r580-lab
```

切回 R535 稳定生产档：

```bash
sudo ./deploy/host/switch-g11-vgpu-branch.sh r535
```

两个命令先完成模块、Hook、manager 和 initramfs 复验，将状态写成
`pending-reboot`，然后自动重启。启动后 `vmate-g11-vgpu-branch-verify.service`
会在任何 `qemu-vm-server.service` 之前复验精确版本、闭源 RM、未签名模块、
manager、mdev types 和本次启动无 XID；全部通过才把状态写成 `ready`。安装器还会
为 `qemu-vm-server.service` 写入同一验收器的 `ExecStartPre`，而 `start-vm.sh`
会直接拒绝残留的 `pending-reboot.state`，因此验收失败不能靠自动服务或手工入口
绕过。`--no-reboot` 只供工程人员检查，状态会保持 `pending-reboot`，此时禁止启动 VM。

Ubuntu 的 DKMS 默认会调用 `kmodsign` 并使用本机 MOK 给新模块签名，即使 Secure
Boot 已关闭。切换器只对自己的 `dpkg`/`dkms` 子进程传入一个不存在的 signer 路径，
让 DKMS 明确跳过签名；它不删除、不生成、不注册 MOK，也不修改全局 DKMS 配置。
模块落盘和加载后，脚本都会要求 `modinfo -F signer nvidia` 输出为空。
`depmod` 索引保持标准可读权限，因此普通用户和 VMate 修复中心可以只读检查驱动；
只有 DEB 缓存、适配源码归档和恢复模块保持 root-only。

因为这里按规则使用未签名模块且 Secure Boot 已关闭，内核日志中的下面一行是预期的
taint 提示，不表示安装了测试签名/自签驱动：

```text
module verification failed: signature and/or required key missing - tainting kernel
```

真正的门禁是 `modinfo -F signer nvidia` 必须为空；若输出任何签名者，切换和冷启动
验收都会失败。

重启后查看自动验收结果：

```bash
systemctl status vmate-g11-vgpu-branch-verify.service --no-pager
./deploy/host/switch-g11-vgpu-branch.sh status
```

第二条必须显示 `脚本记录分支: r535/ready` 或 `r580-lab/ready`；失败会保留
`pending-reboot.state`，不会伪装成 ready。

VMate 安装包中的路径为：

```bash
sudo /opt/vmate/deploy/g11/host/switch-g11-vgpu-branch.sh r535
sudo /opt/vmate/deploy/g11/host/switch-g11-vgpu-branch.sh r580-lab
```

安装包只带脚本，不带 NVIDIA DEB 或 R535 种子。后两者仍来自本机 root-only 缓存。

## 4. R580 母盘该怎样做

本机切到 `r580-lab` 后，可以用可删除克隆安装官方 `582.53` Guest Driver，更新
Windows、Guest Lite 和通用软件，再完整关机。不要把“安装成功/短时有 SDL 画面”
当作稳定性验收。

随后把同一份通用 qcow2 放到 V100/R580.159.01 宿主，完成：

1. 1Q 冷启动，Device Manager Code 0；
2. 驱动 `582.53` 与 WHCP/生产签名；
3. 1920×1080 SDL 持续运行；
4. 2Q 克隆验证；
5. `journalctl -u nvidia-vgpu-mgr` 和内核日志无新增 XID；
6. 正常关机、mdev 回收后再 Sysprep/封盘。

1Q 和 2Q 使用同一份 Guest 驱动和母盘，不需要制作两份基础镜像。

## 5. XID 43、TDR 与 DLS 怎么区分

本机 R580 故障时的原始顺序为：

```text
GPU still processing last submitted push buffer
Failed to copy display head 0 pixels with error 2
Driver Version: 582.53
vGPU license state: Unlicensed (Unrestricted)
XID 43 detected ...
```

含义：

- push buffer 长时间未完成，manager 无法把新 scanout 交给 QEMU/SDL；
- Windows GPU scheduler 超时后触发 TDR；恢复失败时表现为黑屏或 Code 43；
- NVIDIA XID 43 表示发生 software-induced channel fault，该 channel 被终止；
- `Unlicensed (Unrestricted)` 证明该次会话没有处于 DLS 性能限制状态。

NVIDIA 当前的软件许可规则是未取证后先运行 20 分钟，再把帧率限制到 15 FPS；
24 小时后才进一步限制到 3 FPS、CUDA 和部分资源。许可失败应从 Guest 的 NVIDIA
licensing 日志看到明确报错，不应仅凭 SDL 黑屏判断。vGPU 18.0 及以后若正式接入
DLS，官方要求至少 DLS 3.4。

参考：

- <https://docs.nvidia.com/deploy/xid-errors/analyzing-xid-catalog.html>
- <https://learn.microsoft.com/en-us/Windows-hardware/drivers/display/timeout-detection-and-recovery>
- <https://docs.nvidia.com/vgpu/faq/latest/nls.html>
- <https://docs.nvidia.com/vgpu/troubleshooting/latest/licensing.html>

## 6. 故障恢复

只读总诊断：

```bash
./deploy/host/switch-g11-vgpu-branch.sh doctor
```

R580 切换中途失败时，脚本自动尝试恢复并验证 R535。若自动恢复也失败，宿主仍由
AMD 亮机卡输出，重新执行：

```bash
sudo ./deploy/host/switch-g11-vgpu-branch.sh r535
```

不要手工混装 open/closed 模块，不要复制另一内核的 `.ko`。内核升级后旧种子会被
精确内核门禁拒绝；先在新内核重新完成 R535 适配与实机验证，再用：

```bash
sudo ./deploy/host/switch-g11-vgpu-branch.sh init-r535 --force
```

## 7. 交接给其他人的最短清单

交接前确认：

```bash
./deploy/host/switch-g11-vgpu-branch.sh status
sudo test -r /var/lib/vmate/g11-vgpu-branch-switch/r535-seed.state
sudo sha256sum \
  /var/lib/vmate/g11-vgpu-branch-switch/packages/*.deb
```

然后只告诉接手人三条命令：

```bash
./deploy/host/switch-g11-vgpu-branch.sh status
sudo ./deploy/host/switch-g11-vgpu-branch.sh r580-lab
sudo ./deploy/host/switch-g11-vgpu-branch.sh r535
```

不需要交付宿主密码；接手人使用自己的 sudo 权限即可。
