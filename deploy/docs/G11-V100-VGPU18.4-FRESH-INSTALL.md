# G-11 V100 + vGPU 18.4 全新安装教程

本文是 Ubuntu 24.04 新宿主的生产主路径。目标是使用一张 Tesla V100 运行官方
vGPU 18.4，并允许 `V100X-1Q`（1024 MiB）与 `V100X-2Q`（2048 MiB）单独或混合
创建。精确版本为：

- host driver：`570.172.07`；
- Windows guest driver：`573.48` / `32.0.15.7348`；
- 内核：Ubuntu GA `6.8.*-generic`；
- Hook：R570 FB_GET_INFO_V2 460-byte ABI，V100 保持 native capability；
- RAM_TYPE 门禁：R570 只允许精确 1024/2048 MiB，未知档位 fail-closed；
- R580 仍保持 1Q-only 保护，不能把本页的 2Q 结论外推到 R580。

本流程不会开启 Windows `testsigning`/`nointegritychecks`，不会修改 Windows BCD，
也不会创建、注册或安装测试签名/自签名内核驱动。宿主凭据和 Guest 密码只在运行时
输入，不得写入仓库、配置文件或命令行参数。

## 1. 硬件与 BIOS

1. V100 所在插槽对应的 CPU 必须已经安装，并且对应 NUMA node 有在线核心。
2. 宿主显示器接 AMD/Intel 显卡；V100 不作为 `boot_vga`，也不供 GNOME/GDM 输出。
3. BIOS 中启用 VT-d/IOMMU，关闭 Secure Boot。
4. 安装 Ubuntu 24.04 后先联网，并确认系统能看到两张显示适配器。

只读检查：

```bash
lspci -Dnn | grep -Ei 'VGA|3D|Display'
cat /sys/bus/pci/devices/0000:81:00.0/numa_node
cat /sys/devices/system/node/node1/cpulist
mokutil --sb-state
```

示例 BDF `0000:81:00.0` 必须换成实际 V100。若 Secure Boot 仍为 enabled，进入 BIOS
关闭后再继续；不要用 MOK、自签名模块或系统完整性绕过代替。

## 2. 放置官方 18.4 资产

把 NVIDIA 原包解压到当前 VMate 普通用户的固定目录：

```text
/home/ubuntu/Downloads/vGPU18.4/
├── Host_Drivers/
│   └── nvidia-vgpu-ubuntu-570_570.172.07_amd64.deb
└── Guest_Drivers/
    └── 573.48_grid_win10_win11_server2022_dch_64bit_international.exe
```

复核摘要：

```bash
sha256sum \
  /home/ubuntu/Downloads/vGPU18.4/Host_Drivers/nvidia-vgpu-ubuntu-570_570.172.07_amd64.deb \
  /home/ubuntu/Downloads/vGPU18.4/Guest_Drivers/573.48_grid_win10_win11_server2022_dch_64bit_international.exe
```

应分别得到：

```text
37e13ef147fe97f77be44736fb4b9996f67355c1f19ef3da7be48a9a4af34fe9
c49ceac0bbbd578dff628054166959531d38dbe548eb8cc9070509695cb23226
```

这些专有文件只保留在宿主 Downloads、VMate root 资产缓存或 Guest staging 中，不提交
到 Git，也不放入 VMate 安装包。

## 3. 安装 VMate 并一键修复宿主

安装交付的 VMate `.deb`：

```bash
sudo apt install ./vmate_0.1.20_amd64.deb
```

从应用菜单启动 VMate。启动阶段只检查授权，不自动修改宿主。进入“修复中心”，点击
“自动修复”，按桌面提示完成一次管理员授权。

修复器会按顺序完成：

1. 核验双显卡、V100 BDF、NUMA CPU、Secure Boot 和 Ubuntu 版本；
2. 安装固定依赖与受管 WinRM Python；
3. 写入 IOMMU/nouveau 安全配置；
4. 安装并把 Ubuntu GA 6.8 设为保存的默认启动项，保留其它内核作 GRUB 回退；
5. 校验官方 R570 包，构建未签名的闭源 RM DKMS 模块；
6. 安装 R535/R570/R580 ABI fail-closed Hook；R570/V100 使用 native capability；
7. 生成 V100 1Q/2Q mixed 宿主策略，安装 mixed-mode、mdev、CPU 隔离和性能 helper；
8. 完成后独立只读复检。

如果页面提示重启，保存工作后手动重启，再次打开修复中心点击“自动修复”。新宿主通常
需要“准备 6.8 → 重启 → 安装/加载驱动 → 重启 → 最终收口”中的一到两次重启。脚本
不会自动重启，也不会在有 QEMU/mdev 时重启 vGPU manager。

无桌面时可执行同一固定入口：

```bash
sudo /opt/vmate/repair-env.sh g11 \
  --target-bdf 0000:81:00.0 \
  --model v100 \
  --target-uid "$(id -u)"
```

已安装并加载精确 R570、当前正运行 6.8 的宿主会走快速收口：跳过重复的隔离 DKMS
预编译，但仍固定默认内核、更新 initramfs、复核闭源 RM/空 signer、安装最终 Hook 和
mixed 守护。

## 4. 宿主验收

```bash
uname -r
cat /sys/module/nvidia/version
modinfo -F license nvidia
modinfo -F signer nvidia
systemctl is-active nvidia-vgpu-mgr.service
sudo /usr/local/libexec/qemu-vgpu-mixed-mode status 0000:81:00.0
cat /etc/vgpu_unlock/g11-hook.state
```

要求：

- 内核为 `6.8.*-generic`，驱动为 `570.172.07`；
- `license=NVIDIA`，`signer` 为空；
- manager 为 `active`；
- mixed capability=`Supported`、mode=`Enabled`；
- Hook state 包含 `driver_family=r570`、`ram_type_policy=exact-1024-or-2048mb`
  和 `r570_unlock_policy=native`。

宿主策略应为 mixed：

```bash
grep -E 'VGPU_HOST_FB_MODE|VGPU_RESOURCE_PROFILE_1024|VGPU_RESOURCE_PROFILE_2048|VGPU_RM_FB_IDENTITY_MODE' \
  /etc/vmate/g11-vgpu-host.conf
```

## 5. 制作 Windows 10 母盘

ISO 固定使用：

```text
/home/ubuntu/images/iso/win10.iso
```

基础 Windows、VirtIO、VMate Guest 组件、系统设置和封装步骤与原 G-11 母盘相同，唯一
驱动差异是必须安装正式签名的 `573.48`。把 Guest 安装器放到：

```text
/home/ubuntu/images/staging/573.48_grid_win10_win11_server2022_dch_64bit_international.exe
```

通过 VMate/`vmctl.sh driver-install` 的受管 RunOnce 安装，不使用测试签名，不改 BCD。
完成后 Device Manager 必须为 Code 0，`Win32_PnPSignedDriver.IsSigned=True`，签名者为
Microsoft Windows Hardware Compatibility Publisher，驱动版本为 `32.0.15.7348`。

## 6. 1Q、2Q 与混合快速验收

先保证整张 V100 上没有其它 VM/mdev。分别创建 1GB 和 2GB 克隆：

```bash
./deploy/scripts/clone-from-base.sh win10-base 1 \
  --gpu-vram 1024 \
  --platform i7-4820k-p9x79-elpida-8g \
  --ssd-profile samsung-970-pro-512gb

./deploy/scripts/clone-from-base.sh win10-base 2 \
  --gpu-vram 2048 \
  --platform i7-4820k-p9x79-elpida-8g \
  --ssd-profile samsung-970-pro-512gb
```

依次验证：单开 1Q、单开 2Q、最后同时启动 1Q+2Q。每轮检查：

- Guest Device Manager：`Status=OK`、`ConfigManagerErrorCode=0`；
- 1Q：GTX 750 / 1024 MiB；2Q：GTX 750 Ti / 2048 MiB；
- Guest driver：573.48，WHCP 正式签名；
- Guest System 日志没有 Display 4101/TDR；
- 宿主没有 NVIDIA XID、PTE、display-copy timeout；
- 使用 `--graceful-only` 能正常关机，QEMU 退出且 mdev 被回收。

本次物理 V100/R570 实测结果：单 2Q 的 RAM_TYPE 实际从 `15` 写为 `8`；1Q+2Q
混合运行约 5 分钟时两边均执行 `15 → 8`，两台 Guest 均 Code 0/TDR=0，宿主无
XID/PTE/显示拷贝超时，并且两台都能正常关机回收。

## 7. 回滚与排障

- VMate 受管宿主备份：`/var/backups/vmate/`；
- mixed-mode 事务备份：`/var/backups/vmate-vgpu-mixed-mode/`；
- Hook 安装备份：`/var/backups/vgpu_unlock/`；
- 保留的其它内核可从 GRUB Advanced options 启动；
- 修复失败时先保持所有 VM 关闭，查看修复中心末尾输出和
  `journalctl -u nvidia-vgpu-mgr -b`，不要强杀仍在运行的 Guest。

R535/16.4 仍作为旧 RTX 2080 和既有全 1Q 宿主的兼容分支。不要直接覆盖它；使用
受管分支切换器及其内核绑定恢复种子。R580/19.5 只保留历史 name-only/问题定位路径，
不作为本页的统一生产版本。
