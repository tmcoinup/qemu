## 验证方法（可复现）

1. **argv 回归基准**：`start-vm.sh` 的 `DRY_RUN=1` 组装完整 QEMU `argv`、打印（哨兵
   `__DRY_RUN_ARGV__` 分隔）后退出。**无副作用**：不写 profile / 不建 qcow2 / 不拷
   ovmf-vars / 不起 swtpm / 不建 VM 目录 / 不迁移 legacy / 不删 socket / 不 exec。
   钉死一个已存在 profile，重构前后逐字节 `diff`（唯一需屏蔽的随机字段是 SMBIOS
   type=4 `asset=`，既有未持久化行为）。AMD + Intel 两套 profile 均验证 argv 不变。
2. **拆分无损**：bash 拆分用 `sed` 按行段抽取，`cat 子文件 == 原文件体` 逐字节校验，
   再 `bash -n` 全量 + argv harness。
3. **profile 解析**：新解析器对真实 profile 的全部白名单变量与旧 `source` 逐项相等
   （AMD/Intel 两份）+ 注入攻击测试（命令替换/反引号/未登记 key 均拒绝且不执行）。
4. **提取的 Python**：`py_compile` + 与原 heredoc 体 `diff` 字节一致。
5. **NBD helper**：桩 `qemu-nbd` 三场景（空闲连接 / busy+显式→fail-fast / busy+默认→自动选盘）。

### C. profile 安全解析（P1#6）

- `stealth_load_profile` 由 `source` 改为白名单 `KEY=VALUE` 解析（`lib/stealth-profile-io.sh`）：只接受 `_STEALTH_PROFILE_VARS` 登记的 key，值按 `%q` 反转义（sed，不执行），含 `$(...)`/反引号/`${...}` 一律拒绝；**绝不 `source`/`eval`**。save 设 `0600`，load 对 world-writable 告警。
- 单字段读取 `stealth_profile_get KEY FILE`：供只取少数字段的 host 工具用。`host-fix-gpu-devpkey.sh`（原 `bash -c source`）、`host-fix-display-cache.sh`（原 `eval grep`）已改用。

### D. NBD 离线工具安全（P0/P1/P2）

`lib/nbd-lock.sh`（被 7 个 `host-*.sh` source）：

- **全局 `flock`**：串行化所有用 `/dev/nbdN` 的离线工具。
- **`nbd_guard_disk`**：连接前确认 qcow2 未被任何进程打开（防双挂损坏）。
- **`nbd_connect VAR DISK`**：guard + 选盘 + connect，**成功才**置 `_NBD_CONNECTED=1`、记 `_NBD_DEV`。设备 busy 时：用户显式传 `NBD=`（`${NBD:+1}` 记录）→ fail-fast 且**绝不强断**外部连接；未显式 → 自动 `nbd_pick_free` 并经 nameref 就地更新 `NBD`（下游 `${NBD}pN` 随之正确）。
- **`nbd_disconnect_if_owned`**（cleanup 用）：仅当本脚本成功 connect 过才 disconnect。这样 busy fail-fast 退出触发 EXIT trap 时，**不会误断外部连接**。

## 新增/常用环境变量

| 变量 | 作用 |
| --- | --- |
| `DRY_RUN=1` | 仅打印 QEMU argv 后退出；**无副作用**（调试/回归基准） |
| `STRICT_STEALTH=1` | 桥接失败即 fail-fast，拒绝回退 NAT |
| `ALLOW_NAT_FALLBACK=1` | strict 下显式允许回退 NAT |
| `NBD_LOCKFILE=<path>` | NBD 全局锁文件路径（默认 `/run/lock/qemu-stealth-nbd.lock`） |
